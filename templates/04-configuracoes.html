Configurações

Variáveis, feature flags, secrets e limites operacionais. O que muda por ambiente, o que pode ser ajustado em runtime, o que exige redeploy.

Onde Cada Coisa Vive

Três camadas, cada uma com regra clara de uso. Misturar quebra rastreabilidade e dificulta auditoria.

CamadaO que guardaQuem alteraComo muda
appsettings.json Defaults imutáveis (nomes de tópicos, thresholds técnicos, timeouts base) Devs em PR Redeploy
Env vars (ECS task definition) Valores que variam por ambiente (URLs, connection strings non-sensitive) SRE via Terraform Redeploy da task
Secrets Manager Segredos: senhas DB, API keys do antifraude, JWT signing keys SRE com aprovação Segurança Rotação automática 90d ou manual
AppConfig (AWS) Feature flags + limites de contingência (mudanças em runtime) Tech Lead ou Tech Manager Propagação em ~60s sem redeploy

Feature Flags

Vivem em AWS AppConfig, lidas pelo serviço a cada 60s. Permitem ativar/desativar comportamentos sem redeploy. Toda flag tem dono e data de remoção — flags sem dono são removidas trimestralmente em pull request automático.

FlagDefaultEfeitoDonoRemover até
contingencia.habilitada true Permite modo contingência quando antifraude está down. Desligar significa recusar tudo se antifraude cair. Tech Lead permanente
scoring.review_acordo_aceitar true Quando antifraude retorna REVIEW, autorizar e marcar para revisão. Se false, recusa. Risco permanente
pix_debito.habilitado false Aceita channelType PIX_DEBITO. Flag de rollout gradual. Squad Liquidação 2026-08-01
geolocation.exigida_ecomm false Quando ligada, ECOMM sem geolocation tem score reduzido em 15 pontos. Risco 2026-09-30
circuit_breaker.antifraude.threshold 5 Número de falhas em 30s para abrir o circuit do antifraude. SRE permanente

Por que SNS não tem circuit breaker

Publicação no SNS é assíncrona via outbox relay. Se SNS estiver indisponível, o evento permanece em outbox_event com status = pending e o próximo ciclo de relay republica. Circuit breaker aqui só adicionaria complexidade sem benefício — a fila já é nossa camada de absorção.

Regra de ouro de secrets

Nada de senha, chave ou token em appsettings.json, env vars de task definition, repositório git ou pipeline. Sempre Secrets Manager + IAM role no ECS task. Verificado por scan de git no CI (gitleaks) e auditoria de IAM trimestral.

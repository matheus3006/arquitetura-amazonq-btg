Guia: Nova Feature

Walkthrough end-to-end para adicionar uma feature sem quebrar contratos, fitness functions ou padrões da casa. Exemplo concreto: pré-autorização.

Princípios Antes de Começar

  1. Modele o domínio antes do código. Se você não consegue desenhar o agregado em um quadro em 10 minutos, ainda não entendeu o problema.
  2. Contract-first. Defina o OpenAPI YAML antes de qualquer endpoint. Mude o contrato em PR explícito, nunca por acidente.
  3. Testes na ordem de fora para dentro. Domain (rápido) → Application (rápido) → Architecture (rápido) → Integration (lento). Nunca pule.
  4. Documente enquanto implementa. Não no fim. Doc desatualizada é pior que doc inexistente.

Exemplo Concreto: Pré-Autorização

Vamos adicionar a feature Pré-Autorização — segurar valor na conta do cliente sem efetivar a autorização (usado em hotel check-in, locação de veículo, etc.). A pré-autorização tem prazo de captura; expirada, libera o valor automaticamente.

Passo 1 — Modelar Domínio

Liquidacao.Domain/PreAutorizacao/PreAutorizacao.cs
namespace Liquidacao.Domain.PreAutorizacao;

public sealed class PreAutorizacao : AggregateRoot
{
    public Guid PreAuthId { get; private set; }
    public Cpf CustomerCpf { get; private set; }
    public Money Amount { get; private set; }
    public StatusPreAutorizacao Status { get; private set; }
    public DateTimeOffset ExpiresAt { get; private set; }
    public Guid? CapturedAsDecisionId { get; private set; }

    private PreAutorizacao() { }  // EF

    public static PreAutorizacao Criar(Cpf cpf, Money amount, TimeSpan validity)
    {
        if (validity > TimeSpan.FromDays(30))
            throw new DomainException("Pré-autorização não pode exceder 30 dias.");

        var pa = new PreAutorizacao
        {
            PreAuthId = Guid.NewGuid(),
            CustomerCpf = cpf,
            Amount = amount,
            Status = StatusPreAutorizacao.Ativa,
            ExpiresAt = DateTimeOffset.UtcNow.Add(validity)
        };
        pa.RaiseEvent(new PreAutorizacaoCriada(pa.PreAuthId, cpf, amount, pa.ExpiresAt));
        return pa;
    }

    public void Capturar(Guid decisionId)
    {
        if (Status != StatusPreAutorizacao.Ativa)
            throw new DomainException($"Pré-autorização {PreAuthId} não está ativa.");
        if (DateTimeOffset.UtcNow > ExpiresAt)
            throw new DomainException($"Pré-autorização {PreAuthId} expirou.");

        Status = StatusPreAutorizacao.Capturada;
        CapturedAsDecisionId = decisionId;
        RaiseEvent(new PreAutorizacaoCapturada(PreAuthId, decisionId));
    }
}

Passo 2 — Definir Ports

Identifique uma a uma as dependências externas que o use case precisa. Cada uma vira uma interface em Application/Ports/.

Passo 3 — Use Case

Liquidacao.Application/UseCases/PreAutorizar/PreAutorizarHandler.cs
namespace Liquidacao.Application.UseCases.PreAutorizar;

public sealed class PreAutorizarHandler
{
    private readonly IPreAutorizacaoRepository _repo;
    private readonly ISaldoRepository _saldo;
    private readonly IAntifraudeService _antifraude;
    private readonly IEventoPublisher _outbox;

    public PreAutorizarHandler(
        IPreAutorizacaoRepository repo,
        ISaldoRepository saldo,
        IAntifraudeService antifraude,
        IEventoPublisher outbox)
    {
        _repo = repo;
        _saldo = saldo;
        _antifraude = antifraude;
        _outbox = outbox;
    }

    public async Task<PreAutorizarResult> HandleAsync(
        PreAutorizarCommand cmd, CancellationToken ct)
    {
        var saldoOk = await _saldo.HasFundsAsync(cmd.CustomerCpf, cmd.Amount, ct);
        if (!saldoOk) return PreAutorizarResult.Recusado("SALDO_INSUFICIENTE");

        var scoring = await _antifraude.ScoreAsync(cmd.ToAntifraudeRequest(), ct);
        if (scoring.Result < cmd.Channel.GetThreshold())
            return PreAutorizarResult.Recusado("ANTIFRAUDE_LOW_SCORE");

        var pa = PreAutorizacao.Criar(cmd.CustomerCpf, cmd.Amount, cmd.Validity);
        await _repo.AdicionarAsync(pa, ct);
        foreach (var evt in pa.DomainEvents)
            await _outbox.EnqueueAsync(evt, ct);
        await _repo.SalvarAsync(ct);  // commit transacional

        return PreAutorizarResult.Aceito(pa.PreAuthId, pa.ExpiresAt);
    }
}

Passo 4 — Adapters

Implementação concreta de cada port. Polly aplicado sempre que houver chamada externa. EF Core para persistência. Nada de lógica de negócio aqui.

Liquidacao.Infrastructure/Persistence/Repositories/PreAutorizacaoRepository.cs
namespace Liquidacao.Infrastructure.Persistence.Repositories;

public sealed class PreAutorizacaoRepository : IPreAutorizacaoRepository
{
    private readonly LiquidacaoDbContext _db;

    public PreAutorizacaoRepository(LiquidacaoDbContext db) => _db = db;

    public Task<PreAutorizacao?> ObterAsync(Guid id, CancellationToken ct) =>
        _db.PreAutorizacoes.FirstOrDefaultAsync(p => p.PreAuthId == id, ct);

    public async Task AdicionarAsync(PreAutorizacao pa, CancellationToken ct) =>
        await _db.PreAutorizacoes.AddAsync(pa, ct);

    public Task SalvarAsync(CancellationToken ct) => _db.SaveChangesAsync(ct);
}

Passo 5 — Endpoint

Liquidacao.Api/Endpoints/PreAutorizacaoEndpoints.cs
namespace Liquidacao.Api.Endpoints;

public static class PreAutorizacaoEndpoints
{
    public static void Map(IEndpointRouteBuilder app)
    {
        app.MapPost("/pre-autorizar", async (
            PreAutorizarRequest req,
            PreAutorizarHandler handler,
            HttpContext http,
            CancellationToken ct) =>
        {
            var cmd = req.ToCommand();
            var result = await handler.HandleAsync(cmd, ct);
            return result.IsSuccess
                ? Results.Ok(result.ToResponse())
                : Results.Problem(
                    type: $"https://liquidacao.btg.com.br/problems/{result.ReasonCode.ToLower()}",
                    title: result.Message,
                    statusCode: 422);
        })
        .RequireAuthorization()
        .WithName("PreAutorizar");
    }
}

Passo 6 — Testes

Quatro projetos, na ordem:

  1. Domain.Tests: invariantes do agregado. Ex: pré-autorização com validity > 30 dias lança exceção.
  2. Application.Tests: handler com ports faked. Ex: saldo insuficiente retorna recusa sem chamar antifraude.
  3. Architecture.Tests: rodar NetArchTest. Verifica que Domain não importa nada novo, Application não importa Infrastructure.
  4. Integration.Tests: Testcontainers com PostgreSQL real. Verifica que o evento aparece no outbox após commit.

Passo 7 — Documentar

Crie nova página em templates/0X-fluxo-pre-autorizacao.html seguindo o padrão de 07-fluxo-autorizacao.html. Adicione o link no sidebar.js na seção "Fluxos Transacionais".

Checklist de Deploy

  1. Feature flag criada em AppConfig, default false.
  2. Migrations do EF testadas em staging com cópia anonimizada de prod.
  3. Alarmes específicos da feature configurados em CloudWatch.
  4. Runbook operacional atualizado (failure modes, métricas).
  5. Comunicação com consumers downstream sobre o novo tipo de evento.
  6. Plano de rollback documentado e validado.
  7. Tech Lead aprovou release em staging por 48h sem incidentes antes de prod.

Padrões a Evitar

▲
Lógica de negócio no controller

Validação de regra de domínio em endpoint cria duas fontes de verdade. Endpoint só traduz HTTP → command. Validação vive no agregado.

▲
EF Core no Domínio

Annotations [Key], [Required] no agregado violam Hexagonal. Mapeamento vive em EntityConfiguration separada na Infraestrutura.

▲
Publicação fora do outbox

Chamar snsClient.PublishAsync direto do use case quebra atomicidade. Sempre IEventoPublisher.EnqueueAsync que insere na tabela outbox_event na mesma transação.

▲
HttpClient sem Polly

Toda chamada externa exige retry + circuit breaker + timeout. Registrar via AddHttpClient<T>().AddPolicyHandler(...) no Program.cs. Verificado por NetArchTest.
